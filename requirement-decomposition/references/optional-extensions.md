# 可选扩展产物

L3 严格层与高复杂度项目按需纳入（裁剪层级见 `decomposition-rules.md` 开头）。这些产物**不进默认骨架**——`scaffold_docs.py` 不生成它们，按需手工添加到文档网络。添加后走同一套 ID 与链接约定：相对链接被 C03 覆盖；但这些扩展产物的 ID 前缀（IFC/RISK/PERM/DATA/SEC/ENT/BR 等）不在校验器的注册前缀里，ID 悬空与短序号不报——这部分一致性靠人工核，纳入长期项目时可把前缀加进 `RE_ID_TOKEN` 让 C02 接管。扩展产物也要带元信息表（文档版本、状态）与变更记录，否则 C11/C15 会报。

判定要不要纳入：受监管、跨模块分布式事务、多团队并行、高合规要求——命中越多越该加。单一小工具不加。

## 1. 接口契约（`IFC-NNNN`）

模块间、系统与第三方之间的调用契约，是「隐式假设」的重灾区。当模块间通过接口而非共享数据交互时建立。

| 字段 | 说明 |
|------|------|
| 接口 ID / 名称 | `IFC-NNNN`，提供方 / 消费方模块 |
| 协议与传输 | REST / gRPC / 消息队列 / 文件 |
| 请求 / 响应结构 | 字段级定义，链接数据字典 `DATA-NNNN` |
| 错误契约 | 统一错误码 `ERR-NNNN`（code / message / 场景），越权与不存在统一响应 |
| 幂等 / 超时 / 重试 / 限流 | 写操作必须有幂等键 |
| 版本与兼容策略 | 破坏性变更（删字段 / 改类型 / 收紧校验 / 改错误码语义）单独标注 |

## 2. 风险登记册（RAID）

需求阶段的不确定性最该早管。骨架访谈暴露的高风险项在此持续跟踪。

| 字段 | 说明 |
|------|------|
| 风险 `RISK-NNNN` | 描述 / 类别 / 概率 / 影响 / 应对策略 / 责任人 / 触发条件 / 缓解措施 |
| 假设 `ASM-NNNN` | 内容 / 验证方式 / 验证失败后的处置 |
| 问题 `ISSUE-NNNN` | 已发生的阻塞项 / 负责人 / 解决时限 |
| 依赖 `DEP-NNNN` | 外部系统 / 团队 / 第三方，延期风险 |

## 3. 权限矩阵（`PERM-NNNN`）

综述的「角色与权限」只到模块粒度。安全与合规审计需要「角色 × 资源 × 操作」的精确矩阵。

| 字段 | 说明 |
|------|------|
| 角色 | 与术语表、综述角色表一致 |
| 资源 / 操作 | `资源:操作` 粒度（创建 / 读取 / 更新 / 删除 / 审批 / 导出 / 配置） |
| 权限级别 | RBAC 或 ABAC（如「仅本人数据」）；数据级权限（行 / 列 / 字段脱敏） |
| 职责分离 | 如「发起退款者不可审批退款」；默认拒绝原则 |

## 4. 数据字典（`DATA-NNNN`）

术语表管业务概念，数据字典管字段级定义，两者分工。数据实体多、跨模块共享数据多时建立。

| 字段 | 说明 |
|------|------|
| 实体名 / `DATA-NNNN` | 与术语表、状态机一致；标注权威源模块 |
| 字段表 | 名称 / 类型 / 长度精度 / 必填 / 默认值 / 枚举范围 / 唯一 / 外键 / 敏感级别 / 脱敏规则 |
| 生命周期 | 保留期、归档与销毁策略（删除须覆盖备份 / 日志 / 下游 / 缓存所有副本） |

## 5. 威胁模型（`SEC-NNNN`）

安全需求只写「系统应安全」等于没写。含敏感数据或外部接口的系统建立。

- 资产清单、信任边界、攻击面
- STRIDE 逐项建模：伪造 / 篡改 / 抵赖 / 信息泄露 / 拒绝服务 / 提权，每项给缓解控制并链接 `NFR-NNNN`
- 隐私影响评估（DPIA）：数据最小化 / 目的限制 / 同意 / 数据主体权利 / 跨境传输

## 6. 状态机 / 生命周期（`ENT-NNNN`）

核心实体（订单、账户、支付、工单）的状态流转是需求理解的骨架。实体在多个模块间流转时建立，避免各模块各自描述导致状态不一致。

- 状态集合（含初始态、终态）
- 转移表：源状态 → 事件 → 目标状态 → 守卫条件 → 动作/副作用
- 不变量（如「已发货不可再编辑收货地址」）
- 用 Mermaid stateDiagram 表达，标注触发事件的模块 ID

## 7. 业务规则目录（`BR-NNNN`）

业务规则是系统的「算法宪法」，散落各模块易口径不一。同一规则被两个以上模块引用时，收敛到此目录，模块文档引用 `BR-NNNN` 而非本地重述。

| 字段 | 说明 |
|------|------|
| 规则 ID / 名称 / 子域 | `BR-NNNN` |
| 类型 | 约束型 / 推导型 / 行为型 |
| 形式化表达 | 决策表（条件 × 动作）或决策树，多条件组合的规则必须决策表 |
| 责任模块 / 相关实体 / 相关需求 | 链接 `MOD-NNNN`、`DATA-NNNN`、`REQ` |
